# ONY-271: automatic notes after Stop

## Delivered behavior

Settings → Notes model → **Generate notes automatically after Stop** defaults on,
including settings saved before this field existed. Explicit off applies to manual
and detected stops. The preference uses validated, atomic settings writes.

Main emits a capture-specific completion after transcript refinement, final segment
flush and session backup persistence. MeetingView consumes it once, saves the
meeting transcript before AI, and uses the current rough notes and selected
template/provider. Automatic work never falls back from an unavailable external
provider to another model. Existing manual generation fallback remains available.

A synchronous generation lock prevents repeated clicks/duplicate completion from
starting overlapping requests. Capture identity and edit revisions reject old
results after Resume, navigation, title/rough-note/roster/template changes. A
skipped or failed attempt has no pending retry tied to later model/settings changes.
Existing notes and transcript remain available for manual recovery.

## Resume and recovery corrections after human QA

Alec confirmed both on/off Stop workflows in DoodleNote Local 0.4.24, but found
Resume after completed generation stopped transcribing and regeneration/retry
were unclear. Lifecycle metadata pinpointed a previous Stop watchdog terminating
the resumed persistent session 25 seconds after the original Stop.

The watchdog is now canceled on completion, replacement, crash and disposal;
repeated Stop does not create extra timers. A real scripted child-process test
failed before the fix and passes afterward, while wedged stops still escalate.
Production retains its 25-second grace; tests shorten it to 250 ms.

Resume opens the transcript and editable rough notes. Completed notes offer a
labeled **Regenerate notes** action with the template picker. Errors offer direct
**Retry generation** and Settings access while preserving previous generated
notes. The recovery bar and generation button stack without overlap at 800 × 560.

Electron coverage now includes generation completing before Resume, setting on
and off, new transcript plus rough notes in the next request, provider failure
preserving the previous result, retry double-click protection and reopening the
saved result. This remains synthetic capture/provider evidence; human recording
QA must repeat Resume and speak past the previous Stop's 25-second deadline.

## New transcript cue after Resume

Alec confirmed Resume and regenerated content work in human QA, and requested an
explicit bottom cue. The normal bottom Generate notes area now shows **New
transcript detected** directly above **Regenerate notes** when a completed resumed
capture adds transcript segments beyond the generated version. It remains after
failure and reopening, and clears only after successful generation. While capture
or generation is running, the cue stays hidden.

A local optional `enhancedTranscriptSegmentCount` stores the non-echo segment count
used by the generated notes. Older notes establish their current count as a baseline
when resumed; no retroactive freshness is guessed. This cue detects added segments,
not edits to existing transcript text. The field is local meeting metadata; no cloud
schema, provider, or recording behavior changes. The existing Regenerate action
remains available even when no new transcript is detected.

The Electron workflow verifies the cue in the bottom action area, persistence before
regeneration/reopen, visibility after provider failure, and clearing after success.
The meeting-store test verifies the marker survives transcript-only patches and a
fresh store instance, rejects invalid counts, and advances on generation success.

## Check this: human macOS QA

Use a separate development profile and only synthetic meeting content:

```sh
pnpm install --frozen-lockfile
pnpm engine:build
DOODLE_USER_DATA="$(mktemp -d)" pnpm --filter desktop dev
```

1. Complete model/permission setup in that test profile. In Settings → Notes model,
   confirm the new switch starts on. Turn it off, restart using the same profile
   path, and confirm it remains off. At an 800 × 560 window, scroll to the row;
   the label, help text and keyboard-operable switch must remain accessible.
2. Turn it on, record a short test meeting, add rough notes and select a template.
   Stop manually: transcript/audio should finish saving before notes appear once.
   Repeat with a supported meeting app's detected ending; expect the same result.
3. Turn it off and repeat both Stop routes: transcript/audio save, no AI runs,
   and Generate notes remains available. Click Generate notes; expect one result.
4. While generation runs, edit rough notes or Resume recording: the old result
   must not replace newer work. Finish the resumed capture; its transcript includes
   both recording parts. Confirm notes and transcript after reopening/restart.
5. After generation has completed, Resume within 25 seconds of Stop. Continue
   speaking for at least 35 seconds. Confirm live transcript and rough notes are
   editable; Stop and check both recording parts. With the setting off, use the
   bottom New transcript detected cue and Regenerate notes button; reopen before
   generating to confirm the cue persists. After successful generation the cue
   disappears. With it on, expect one automatic generation.
6. Exercise a missing model/key and a failing provider in the test profile: expect
   a clear recovery/setup message and saved transcript/audio. Fix the setup;
   generation should require a manual click, with no delayed automatic retry.
