# DEV-417: bounded note generation

Issue: https://app.notion.com/p/3f1f0f846ee481d9b92bfdaf8f055c4f

Tested on macOS arm64, 2026-10-06. This is source/development-runtime evidence, not an installed release acceptance record.

## Change and limits

The local model previously received neither an output cap nor an abort signal. Condensation also caught cancellation as an ordinary failed section and continued the rest of the pipeline. A pre-fix regression reproduced that continuation.

Each local request now supplies the native runtime's `maxTokens` and `signal` and reads `promptWithMeta.stopReason`. Limits include prefill and decoding:

| Phase | Deadline | Output cap |
| --- | --- | --- |
| Model selection/loading | 120 seconds | None; no generation |
| Each condensation section | 180 seconds | 2,048 tokens |
| Final writing or single-pass notes | 300 seconds | 4,096 tokens |

These are safety ceilings, not promised completion times. The condensation prompt asks for at most 30 concise bullets/900 words and deduplicates repeated discussion. The 36,000-character section size, overlap, full-transcript section traversal, templates, speaker rules, model selection and provider consent remain intact. The shared local raw-generation primitive also applies the writing ceiling to local Ask responses.

Abort and deadlines stop the producer through the native signal. Context disposal completes before the promise settles, and service ownership remains held until that settlement. There is no abandoned `Promise.race` or early busy reset. Output-cap exhaustion is an explicit error, never a successful truncated summary. Ordinary section failures retain the existing marked-gap behavior; abort/deadline/output-cap errors stop the entire pipeline.

Renderer, preload and main use a meeting ID, unique run ID and sender ownership. Edits, Resume, unmount, renderer crash/reload and explicit Cancel invalidate pending work. Progress is scoped to the matching run and shows phase, part, elapsed time and age of the last model response. No intermediate text is logged. Cancel remains disabled while cleanup finishes. Once an accepted result begins saving, the UI explicitly switches to Saving and no longer offers cancel. Previously saved notes, rough notes, transcripts and recordings are not cleared on error/cancel.

The optional cloud path forwards the abort signal through the AI SDK and rejects its length-limited response. Provider choices, keys, consent and defaults are unchanged. No schema or data migration.

## Real cached model evidence

`pnpm --filter @repo/ai long-meeting-smoke` passed using the existing Qwen3-4B-Instruct-2507 Q4_K_M GGUF on Metal. The test now requires an existing cached file, exercises native cancellation followed by retry, and has a 12-minute isolated-process watchdog. No model download and no private transcript are used.

- Native cancellation from the first output callback settled with context cleanup. The entire first operation, including cold load and prefill, took 12,919 ms.
- Retry processed 404 synthetic segments, 77,110 formatted characters, all three condensation sections and final writing in 131 seconds.
- All four planted checks passed: early audit budget, middle launch date, middle renewal owner, and late rollout-plan owner.
- These facts demonstrate useful normal long-meeting completion after cancellation. They are not a general summary-quality guarantee or a performance SLA. The original installed app remained running during this bounded isolated test, so timing is not an exclusive-machine benchmark.

The native implementation supports cooperative abort during model loading and generation. Context allocation/disposal themselves have no abort API; ownership deliberately remains held until they finish. Real cancellation settled in this Mac test. Driver-level deadlocks are not proven recoverable by this in-process design; if target-platform QA demonstrates non-settling native cleanup, isolate the model runtime and terminate only that process before release. Do not dispose a context still in use or permit overlapping retry.

## Check this before release

1. In an isolated compatible Mac build with cached Qwen, generate a short meeting and a multi-section meeting. Expect saved, useful notes with middle facts, then reopen and confirm persistence.
2. Cancel during preparation, condensation and writing. Expect a cleanup state, no changed notes or lost sources, and a successful manual retry without restarting.
3. Edit rough notes, Resume, switch meetings, or reload the renderer while generation is pending. Expect stale progress/results to be ignored and no overlapping model run.
4. Exercise output-cap/deadline/model failure. Expect an actionable error, preserved prior notes and sources, and retry only after cleanup.
5. Repeat target Windows cancellation/cleanup behavior and accessibility checks independently. CI packaging alone is insufficient.
