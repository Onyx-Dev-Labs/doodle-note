# Local pre-meeting brief context

DEV-509 is being implemented in an approved stack above PR230 and DEV-507. The independent calendar/context modules do not expose a complete brief feature. Entry points, the actual shared CitedAskService, source navigation, owner-scoped IPC, quality evaluation and packaged QA must be integrated and verified before enabling it.

Calendar invitee observations are separate from acoustic speakers. Provider, account, calendar and occurrence keys retain their existing algorithms. Names, domains, address aliases and case changes never merge people. Resource entries cannot become people. Google calendar-self and Graph delegated organizer metadata do not prove authenticated self. The current account cache lacks the required verified address ownership evidence, so production observations leave self unknown until user correction. No additional provider request or permission is introduced. Provider references: [Google Events](https://developers.google.com/workspace/calendar/api/v3/reference/events), [Microsoft attendee](https://learn.microsoft.com/en-us/graph/api/resources/attendee?view=graph-rest-1.0), [Microsoft event](https://learn.microsoft.com/en-us/graph/api/resources/event?view=graph-rest-1.0).

`calendar-context-v1.json` is **plaintext local user content** at the library root. It contains immutable event/invitee observations, user-created person/company IDs and append-only correction/link provenance. It contains no calendar credentials or generated briefs. The existing canonical source identity reader binds it to local null/null SourceScope independently of sign-in. This module never creates or repairs the source marker. It waits for source-worker initialization and fails closed on unsupported/corrupt/mismatched data.

Writes are serialized under the existing library lease, revision checked, external-byte-digest fenced and published by private temporary file, fsync, exact-byte verification and atomic rename. A dedicated codec worker handles JSON and file hashing. Indexed strict validation yields between bounded batches; main owns the final fence and publication. Unknown JSON fields survive supported edits. There is a 16 MiB admission bound, with no automatic pruning. At capacity the user can explicitly forget an account's known saved observations/entities/corrections after a revision-bound preview; ordinary disconnect preserves them. Unknown extension fields are preserved, not guessed to belong to an account. Forget never deletes meetings/audio or credentials. Unlink retains historical provenance.

The relocation allowlist includes exactly this sidecar. A move carries its bytes and the source identity with the library. The previous path is not an active source after switching. Older versions ignore the sidecar and older relocation code may leave it behind: preserve the file before moving a library with an older binary. Disabling or rolling back briefs keeps this file and all originals; only generated memory state should be evicted.

Accepted-start metadata observes the common reservation coordinator. Attach is too early to persist an association: a new original may not exist yet. Main must pass the matching accepted engine-attempt token and actual capture ID after successful live start, then validate the original and all event/account/library fences through commit. Newly created eligible originals can receive an event/snapshot link. Consecutive unchanged observations reuse their snapshot. A content reversion creates a new immutable observation carrying the latest exact-identity occurrence corrections; historical meeting snapshots stay fixed. Existing snapshotless notes require explicit history review; Resume keeps established snapshot links. Today’s roster never proves historical attendance or who spoke. Optional metadata failure reports a non-blocking warning and cannot interrupt valid audio. No participant or original-text writes are made by these modules.

Synthetic tests cover normalization, strict cache/schema/reference checks, immutable corrections, account isolation, external edits, atomic failures, capacity, forget, relocation and coordinator ownership. They do not establish actual Google/Microsoft account behavior, native notifications, permission prompts, recording, local-model quality or installed-app acceptance. Those gates remain explicit in the approved [spec](../../../docs/superpowers/specs/2026-10-18-dev509-calendar-briefs.md) and [plan](../../../docs/superpowers/plans/2026-10-18-dev509-calendar-briefs.md).


## Dense context verification (2026-10-18)

Independent review found and reproduced two defects in checkpoint `50f7165`: historical digest reuse resurrected an older match after A→B→A, and per-link full-map reference checks stalled main for 3.15 seconds on 6,000 valid snapshots/links. Regression tests now cover unassignment/self carry-forward without rewriting the old snapshot, full tail-reference rejection, and cancellation during incremental validation. Reference indexes remove the quadratic lookup; the same complete validator is consumed synchronously by direct callers or cooperatively by the store. No schema/digest/reference check was removed. Returned decoded documents no longer require a second large main-thread clone; the store retains only its private revision/digest fence.

Reproduce the synthetic dense read/atomic-write probe with `pnpm --filter desktop exec tsx scripts/calendar-context-benchmark.ts`. Twenty read/write iterations on Node24.22.0, Darwin arm64: at995,187 bytes/600 records, loop p95 9.39ms/max11.44ms;4,987,187 bytes/3,000 records, p95 5.84ms/max19.11ms;9,980,189 bytes/6,000 records, p95 4.71ms/max24.14ms;16,640,189 bytes/10,000 records, p95 4.69ms/max30.69ms. Corresponding read/write p95 at the largest fixture:161.26ms/351.51ms. These fixtures contain real v1 observations and accepted-start links, not padding. The loop p95 target≤16ms passed this run; transient maxima remain reported and this is not native capture, provider, inference, packaged performance or universal timing qualification. Initial small-fixture samples overlapped local type/lint/tests; larger samples followed their completion. The prior padded-file benchmark alone was insufficient.
